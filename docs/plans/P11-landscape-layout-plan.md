# タブレット横持ちレイアウト対応(練習画面・キャリブレーション画面)実装計画

## 背景・目的

実機(Galaxy Tab A11+)を三脚に固定し、カメラの前に鏡を置いて鍵盤を写す構成で使う予定。
タブレットは**横持ち**で使うため、画面も横持ち前提にしたい(開発者要望 2026-10-19)。

現状の問題(CSS 上 960×600 相当で確認):

- 縦に積む作りのため、練習中に使わないもの(曲選択・楽譜追加・MIDI 機器選択・Bluetooth の案内文・バーチャル鍵盤)が
  画面の大半を占め、肝心の「次に弾く音」が小さく、スクロールしないと全体が見えない
- キャリブレーション画面は、ガイド文が上・カメラプレビューが下にあるため、
  横持ちだと**手順を読みながらカメラを見られない**

完了条件:

- **タブレット横持ち(960×600 相当)で、折りたたみを閉じた状態なら、
  練習画面の主要情報(曲名・次に弾く音・直前の判定・カメラ映像・操作ボタン)がスクロールなしで収まる**
- 同じ条件で、キャリブレーション画面の**ガイドとカメラを同時に見られる**
- 縦持ち・PC でもこれまでどおり崩れない

## 画面の構成(横持ち時)

### 練習画面 S-04

```
┌─────────────────────────────────────────────┐
│ 練習 / 曲名 / 打鍵・ミス数 / MIDI状態    [⚙] │ ← ヘッダ(1 行、h1 を統合)
├──────────────────┬──────────────────────────┤
│                  │ 次に弾く音(1/9)           │
│  カメラ映像       │ ド4 (指1 / 右)      ←特大 │
│  (手の認識確認)   │ 1 小節目の 1 番目         │
│                  │ ─────────────────────── │
│                  │ 直前の判定(色つき)        │
├──────────────────┴──────────────────────────┤
│ [一時停止][やり直す][_小節から▶][結果][設定]  │ ← 操作バー(1 行)
├─────────────────────────────────────────────┤
│ ▼ 準備(曲・楽譜追加・MIDI 機器・Bluetooth)  │ ← 折りたたみ(既定: 閉)
│ ▼ バーチャル鍵盤                             │ ← 折りたたみ
│ ▼ 判定ログ                                   │ ← 折りたたみ(既定: 閉)
└─────────────────────────────────────────────┘
```

**高さの見積もり(960×600、折りたたみは全て閉)**

| 要素 | 高さ |
|---|---|
| `#root` の上下 padding | 32 |
| 音声案内バナー(横持ちでは 1 行に細く。消えたら 0) | 30 |
| タブバー(横持ちでは padding と余白を縮小) | 34 |
| ヘッダ行(h1 を統合) | 40 |
| カメラ列 = ミラーchk 24 + 映像(高さ上限 36dvh = 216)+ fps 注記 20 | 260 |
| 操作バー(1 行。ボタン min-height 36) | 44 |
| 折りたたみの見出し × 3 | 84 |
| **合計** | **約 524** |

→ 600 に対して余裕がある。情報列(次に弾く音)はカメラ列の高さ 260 の中に収まる。

- 「準備」の中身は**今あるものをそのまま移すだけ**(機能は変えない)
- ヘッダには、畳んだままでも分かるように**曲名**と**MIDI の接続状態**を小さく出す
- 折りたたみの既定(初回表示時に 1 度だけ決める):
  - 準備 … **閉**
  - 判定ログ … **閉**
  - バーチャル鍵盤 … **実機の MIDI が未接続なら開 / 接続済みなら閉**
    (F-02 の代替手段をすぐ使えるように。開いた場合は 200px 増えてスクロールが出るが、
     完了条件は「閉じた状態」で判定する)
- 開閉状態は画面を開いている間だけ保持する(保存しない。設定・状態はメモリ内保持という既存方針に合わせる)
- ボタンのラベルを短くする(高さと折り返し対策):
  「最初からやり直す」→「やり直す」、「練習を終了して結果を見る」→「結果を見る」、「⚙ 設定」はヘッダへ移動

### キャリブレーション画面(P3 / S-02 相当)

```
┌──────────────────┬──────────────────────────┐
│                  │ 手順 n: ガイド文          │ ← 右列は高さ上限 + 内部スクロール
│  カメラプレビュー │ [この位置で確定][やり直す] │   (上段のみスクロール)
│  (大きく)         │ ズレ一覧 / 指特定の結果    │
│                  │ ─────────────────────── │
│                  │ バーチャル鍵盤(高さ縮小)   │ ← 下段に固定。常時表示
├──────────────────┴──────────────────────────┤
│ ▼ 設定(カメラ選択・ミラー・MIDI 機器)       │ ← 折りたたみ(既定: 閉)
└─────────────────────────────────────────────┘
```

- 右列は `max-height` + `overflow-y: auto` にする(ガイド文が長い手順でも画面が伸びない)
- ズレ一覧・指特定の結果は**件数を減らさない**(右列が内部スクロールするため、高さの問題は起きない。
  件数を削ると手順 5 の確認材料が減るので、そのままにする)
- **カメラの起動に失敗しているとき(`cameraState === "error"`)は、
  カメラ選択と再試行を折りたたみの外に出す**(別のカメラを選び直す導線を隠さないため)
- バーチャル鍵盤は**折りたたまず、右列の下段に常時表示**する(ウィザードは打鍵しながらカメラを見る操作のため)。
  横持ち時は `.compact-keys` で高さを縮める。鍵数・オクターブシフトは変更しない
- `<h1>キャリブレーション・指特定</h1>` も練習画面と同様にヘッダ 1 行へ統合する

## 実装方針

### 1. `components/CollapsibleSection.tsx`(新規)

```tsx
interface Props { title: string; summary?: string; defaultOpen?: boolean; children: React.ReactNode }
```

- `<details>` / `<summary>` を使い、開閉はブラウザに任せる
- **`defaultOpen` は `useState` で初回の値を 1 度だけ凍結し、以後 `open` 属性を React から書き換えない**
  (そうしないと、練習中にキーボードが接続された瞬間に React が `open` を上書きし、
   利用者が開いたセクションが勝手に閉じる)
- `summary` には畳んだままでも分かる補足(曲名、接続中の機器名など)を出す

### 2. `index.css`(レイアウト規則)

- 冒頭コメントを仕様書 9 章(タブレット横持ちが基本)に合わせて書き直す
- 横持ちの判定: `@media (orientation: landscape) and (min-width: 800px) and (min-height: 500px)`
  (`min-height` を足して、横持ちスマホ(高さ 390px 程度)で 2 列にならないようにする)
- 追加するクラス:
  - **横幅の拡張はしない**(`#root` の `max-width: 900px` のままにする)。
    960px の実機では既に内容幅 868px を使っており、広げても 28px しか増えないため、
    `#root` を触って P1/P2 に波及させるリスクに見合わない
  - `.practice-top`(既存): カメラ列 45% / 情報列 55%(情報列を広く)
  - **`.cam-frame`(新規・重要)**: カメラ映像のラッパーに付け、
    `width: min(100%, calc(36dvh * 4 / 3))` のように**アスペクト比から幅を逆算して絞る**。
    `video` / `canvas` に `max-height` を直接付けてはいけない(下記「禁止事項」)
  - `.calib-top`(新規): キャリブレーション画面の 2 列(カメラ左・ガイド右)。
    右列は `display: flex; flex-direction: column; max-height: 52dvh` とし、
    **上段(ガイド・ボタン・一覧)だけ `overflow-y: auto`、下段のバーチャル鍵盤は固定**にする
    (鍵盤がスクロールの中に埋もれると「カメラと同時に見える」目的が崩れるため)
  - `.compact-keys`: 横持ち時だけバーチャル鍵盤の高さを 160px → 100px 程度に縮める。
    **鍵数・オクターブシフト(±)は変更しない**(F-02 の要件なので、見た目の高さだけを変える)
  - `.app-tabs` / `.app-tab` / `.audio-notice`: タブバー・タブボタン・音声案内バナーのスタイル。
    **現在インラインで書いている padding / fontSize / marginBottom を CSS 側へ移す**
    (インラインスタイルは CSS クラスより強く、クラスを足しただけでは縮まないため)。
    横持ち時だけパディングと余白を縮める
  - 操作ボタンの `min-height: 36px` を横持ちでも適用(タブレットもタッチ操作のため)
- 縦持ち・狭い画面ではこれらを当てず、**今までどおり縦積み**
- 高さの単位は `dvh`(アドレスバーの出入りで高さが変わるため)

### 3. `App.tsx`

- 横持ち時にタブバーを細くする(`.compact-tabs` を付ける)
- 音声案内バナー(「🔇 画面を一度タップ」)を横持ちでは 1 行の細い表示にする
- **タブの構成・状態・ハンドラは変更しない**

### 4. `PracticeScreen.tsx`

- JSX の並べ替えと `CollapsibleSection` での包み直しが中心。**状態管理・判定呼び出しは変更しない**
- `<h1>練習(S-04)</h1>` を廃し、ヘッダ行に統合(曲名・カウント・MIDI 状態・設定ボタン)
- 「次に弾く音」のフォントサイズを `clamp()` で画面幅に追従させる(遠目でも読める大きさを維持)
- バーチャル鍵盤の既定開閉は `midi.isSelectedConnected || midi.bluetooth.status === "connected"` で判断
  (どちらも `useMidiDevices` に実在することを確認済み)
- カメラ映像のラッパーに `.cam-frame` を付ける

### 5. `CalibrationDebug.tsx`

- カメラプレビューを 2 列の左へ、ガイド・ボタン・ズレ一覧・バーチャル鍵盤を右へ
- カメラ選択・ミラー・MIDI 機器選択を下部の折りたたみへ(カメラエラー時は外に出す)
- 一覧の表示件数を横持ち時 5 件に絞る
- **キャリブレーションの手順・判定ロジックは変更しない**

## 禁止事項(この変更で壊しやすい点)

1. **`video` / `canvas` に `max-height` を直接付けない。**
   `<canvas>` は親に対して `width:100%; height:100%` で重ねているため、
   `video` にだけ高さ制限が効くと映像がレターボックス表示になり、
   **ランドマークと白線オーバーレイが実際の手とずれる**(キャリブレーションの目視確認が成立しなくなる)。
   高さを抑えるときは**ラッパーの幅をアスペクト比から逆算して絞る**こと
2. **バーチャル鍵盤を条件レンダリング(`{open && <VirtualKeyboard/>}`)にしない。**
   `VirtualKeyboard` は `window` の keydown/keyup を購読して PC キー入力(F-02)を受けているため、
   アンマウントすると閉じている間キー入力が死ぬ。必ず `<details>` の中に**常時マウント**する
3. `<details open={変化する値}>` のように、変化する値を `open` に渡さない(上記 1. の `CollapsibleSection` 参照)

## テスト・確認

- `npm run test`(183 件)が全て通ること。`npm run build`(内部で `tsc --noEmit` も走る)が通ること
- ブラウザでの確認(dev サーバー):
  1. **960×600(タブレット横持ち相当)**: 折りたたみを閉じた状態で、
     曲名・次に弾く音・直前の判定・操作ボタン・カメラが**スクロールなし**で見えること
  2. 同サイズでキャリブレーション画面が、カメラとガイドを同時に見られること
  3. **390×844(スマホ縦持ち相当)**: 縦積みで、横スクロールが出ないこと
  4. **1280×800(PC)**: 崩れないこと
  5. **一時的に `overflow-x: auto` にして**、2 列化で横にあふれていないことを確かめる
     (`index.css` の `overflow-x: hidden` は破綻を静かに隠すため)
  6. 折りたたみを開くと、曲選択・楽譜追加・MIDI 機器選択・Bluetooth 接続・バーチャル鍵盤が
     今までどおり使えること(F-01 / F-02 / F-09 / F-10)
  7. バーチャル鍵盤で打鍵し、判定・表示・参照音が動くこと。**閉じた状態でも PC キー入力が効くこと**(F-02)
  8. **カメラのランドマーク・白線が手の位置とずれていないこと**(960×600 と 390×844 の両方で)
  9. 960×600 で結果画面(S-05)と設定モーダル(S-06)を開き、ボタンに到達できること
  10. **折りたたみの既定が勝手に変わらないこと**: 鍵盤セクションを手で開閉したあと、
      MIDI 機器の選択をバーチャル ↔ 実機で切り替えても、開閉状態が変わらないこと
  11. カメラ映像の高さが想定どおり(画面の約 1/3)であること。
      端末が 4:3 以外の映像を返しても大きく崩れないこと
  12. 両手の曲(2 音同時)で「次に弾く音」が不自然に折り返さないこと
- 実機確認(開発者に依頼): タブレット横持ちで練習画面・キャリブレーション画面が収まること

※ カメラの起動に失敗しているとき(エラー表示と再試行ボタンが出ているとき)は、
  スクロールが出てもよい。仕様書 10 章が求める導線なので、表示を抑制しない

## 技術的な注意点

- インラインスタイル中心のコードなので、**レイアウトに関わる部分だけ className を使う**
  (既存の `.practice-top` / `.practice-cam` / `.practice-info` と同じ流儀)
- `<details>` の中身は閉じていても DOM に存在するため、カメラ・MIDI の購読や判定は止まらない
  (ただし「禁止事項 2」のとおり、条件レンダリングに変えると止まる)
- キャリブレーションは MediaPipe の正規化座標(0〜1)だけを使っており、
  画面上のクリック座標は使っていない。したがって**表示サイズを変えても手順の判定はずれない**。
  ずれるとすれば「禁止事項 1」のオーバーレイ表示のほうなので、そちらを目視で確認する
