## 実装内容

### 1. 雛形

- `npm create vite@latest`(react-ts テンプレート)相当の構成を現ディレクトリに展開
- TypeScript strict モード有効
- Vitest を devDependency に追加し、`npm run test` を用意(外部ライブラリ追加はこれと React/Vite 一式のみ)
- `resolveJsonModule` 有効化(楽曲 JSON の import 用)

### 2. `src/core/` 判定エンジン(純 TS・ブラウザ API 非依存)

**types.ts**: 仕様書 8.1 スキーマの型(`Song`, `ScoreEvent`, `Note`(`midi`/`finger: number|null`/`hand: "L"|"R"`))と、Note On 処理結果の型:

- `correct` — 期待音と一致(note 達成。イベント全達成ならカーソル前進)
- `wrongNote` — 音ミス(カーソルは進めない)
- `duplicateIgnored` — 達成済み構成音の再打鍵(無視、ミスにしない)
- `skipJump` — 弾き飛ばし救済によるジャンプ(スキップされたイベント index 一覧を含む)
- `finished` — 最終イベント達成(演奏終了)

**scoreFollower.ts**: クラス `ScoreFollower`。状態 = カーソル index、現イベントの達成済み構成音、同一カーソル位置での連続音ミス数。`processNoteOn(midi, timestampMs)` が上記結果を返す。仕様 7.1 の全ルールを実装:

- 和音: 構成音を順不同で達成、全達成でカーソル前進。構成音以外は音ミス(達成マークはリセットしない)。達成済み音の再打鍵は無視
- 同音連打: イベントごとに新しい Note On が必要
- 弾き飛ばし救済(挙動をレビューで確定済み):
  - 発動条件: 同一カーソル位置で 2 回連続音ミス。ただし**現在カーソルのイベントが和音(部分達成中含む)の場合は発動しない**(「和音イベントには適用しない」の安全側解釈)
  - 探索: 直後 N イベント(N=2、constants.ts でパラメータ化)以内に、直近のミス音と一致する**単音イベント**を探索(和音イベントは一致候補にしない)
  - 一致あり → カーソルをジャンプし、その打鍵でジャンプ先イベントを達成扱い(弾き直し不要)。**詰まっていた現在イベント自身を含む**、ジャンプ先より前の未演奏イベントすべてを「スキップ(未演奏)」として結果に含める
  - 救済を発動した 2 打鍵目は、仕様の文言どおり**音ミスとして記録された上で**ジャンプが起きる(= 音ミスカウントは残し、結果型は `skipJump` にミス記録情報も含める)
- 最終イベント達成で `finished`

**constants.ts**: `SKIP_SEARCH_RANGE = 2` 等。「実機での予備実験で調整するパラメータ」と日本語コメント明記(7.2 の閾値定数も P3 でここに集約する前提の置き場)

音判定(7.3)は「スコアフォローの照合結果そのまま」なので、独立した judge.ts は P1 では作らない(運指判定と統合する P4 で追加)。

### 3. バーチャル MIDI(F-02)

- `src/midi/types.ts`: `MidiSource` インターフェース(`onNoteOn` / `onNoteOff` コールバック、ノート番号 + タイムスタンプ)。判定エンジンは Note On のみ使うが、「実 MIDI デバイスと同じインターフェース」とするため Note Off も含める
- `src/midi/virtualKeyboard.ts`: PC キーボード割当(A=ド, W=ド♯, S=レ, E=レ♯, D=ミ, F=ファ, T=ファ♯, G=ソ, Y=ソ♯, H=ラ, U=ラ♯, J=シ, K=高いド)とオクターブシフト状態を管理し `MidiSource` を実装
- `components/VirtualKeyboard.tsx`: 2 オクターブ分の鍵盤 UI(クリック/タップで Note On/Off)+ オクターブシフト ± ボタン。キー配置は README に記載

### 4. テスト曲データ(8.3)

`src/songs/doremi.json`: ドレミファソファミレド = MIDI 60,62,64,65,67,65,64,62,60 / 指番号 1,2,3,4,5,4,3,2,1 / 全て `hand: "R"`。仕様書 8.1 スキーマに**完全準拠**(トップレベル `id` / `title` / `difficulty`、イベントごとの `index` / `measure` / `posInMeasure`)。9 音を 4+4+1 で 3 小節に配置。

### 5. 最小動作確認画面(P1 用)

`PracticeDebug.tsx`: テスト曲を読み込み、「次に弾くべき音(音名と指番号)」「直前の判定結果(正解 / 音ミス / スキップ / 終了)」を大きく表示 + バーチャル鍵盤。※S-01〜S-06 の正式な画面は後続フェーズで実装。これは P1 完了条件の確認用の仮画面。

### 6. ユニットテスト(`tests/core/scoreFollower.test.ts`)

- 正しい順で弾くと全イベント達成 → `finished`
- 間違った音で音ミス、カーソルが進まない、弾き直しで回復
- **同音連打**(仕様で「必ず含めること」と明記): 同じ音の連続イベントで、Note On のたびに 1 つずつ進む
- 和音: 順不同達成 / 構成音以外は音ミス(達成マーク維持)/ 達成済み音の再打鍵は無視
- 弾き飛ばし救済: 2 連続音ミス → N=2 以内の一致でジャンプ / スキップ記録に現在イベント自身が含まれる / 2 打鍵目の音ミス記録が残る / ジャンプ先候補に和音イベントは含めない / 現在イベントが和音のときは発動しない / 範囲外なら救済しない

## 検証方法

- `npm run test` が全件パス
- `npm run dev` で起動し:
  1. バーチャル鍵盤をクリック(または A,S,D,F,G キー)でドレミファソファミレドを正しく弾く → 各打鍵で「正解」表示、最後に「終了」
  2. わざと違う鍵盤を押す → 「音ミス」表示、進行位置が進まない
  3. オクターブシフト ± で発音ノート番号が変わる

## 仕様上の解釈(サブエージェントレビュー済み)

- 弾き飛ばし救済の「単音イベントのみ対象」は「発動元(現在カーソル)・ジャンプ先とも単音イベントに限る」と解釈(上記「実装内容 2.」に確定挙動を記載)
- ジャンプを引き起こした打鍵はジャンプ先イベントの達成として扱う(音ミス記録は残す)
- コメントはすべて日本語。`src/core/` は DOM / Web API を一切 import しない
