# P4 実装計画: 運指判定の統合(7.3) + ビープ音(F-05) + 練習画面(S-04)

## 目的

仕様書 11 章 P4「運指判定の統合 + フィードバック音 + 練習画面完成」を実装する。
完了条件: **テスト曲でわざと違う指で弾くとビープが鳴る**。

## 仕様書の該当章

- 7.3 判定: 音判定はスコアフォローの結果そのまま / 運指判定は音が正解だった note について推定指番号と譜面指番号を比較 /
  判定不能は設定に従い「無視(カウントのみ)」or「ミス扱い」/ 音ミスの打鍵は運指判定の対象外
- F-05 練習モード: カメラプレビュー+ランドマーク / 進行位置(次に弾くべき音と指番号)表示 /
  運指ミス=ビープ A(低め・ブザー的)+「指番号: 正解 3 / 実際 2」表示 / 音ミス=ビープ B(音色を変える)/
  正解=無音 / 一時停止・最初からやり直し・小節番号指定の途中開始(内部で先頭イベント index に変換)/
  判定ログ記録(タイムスタンプ、譜面上の位置、期待値、実測値、判定結果)
- 8.1: `finger: null` の音符は運指判定をスキップ
- F-01: 「カメラなし(音判定のみ)モード」— キャリブレーション無しでも練習できる
- 5 章: 音は Web Audio API(ビープ音生成のみ)
- 10 章: Note On からフィードバック音まで 200ms 以内

## 実装内容

### 1. 判定エンジン統合 `core/judge.ts`(純 TS)

`PracticeJudge` クラス。内部に `ScoreFollower` を持ち、Note On 1 回を受けて
音判定(7.1/7.3)→ 運指判定(7.2/7.3)を一気通貫で行い、判定ログエントリを返す・記録する。

```
handleNoteOn(midi, timestampMs, frame: LandmarkFrame | null, calibration: KeyboardCalibration | null)
  → JudgmentEntry
```

処理(仕様書 7.3 を忠実に):
1. `scoreFollower.processNoteOn(midi)` で音判定
2. 音ミス(wrongNote)→ 運指判定はしない(音を直すのが先)。ビープ B
3. **弾き飛ばし救済(skipJump、および skippedEventIndices 付きの finished)→ この打鍵は仕様 7.1 の
   文言どおり「音ミスとして記録」されるため、運指判定はしない(7.3)。ビープ B。
   集計上も音ミス 1 回として数える。スキップされたイベントは「スキップ(未演奏)」としてログに記録**
   (レビュー指摘 1: finished を一律に運指判定対象にすると 7.3 違反になる)
4. 正解(correct / スキップ無しの finished)→ 達成した note について運指判定:
   - `note.finger === null` → 運指判定スキップ(8.1)。ログ上は「運指判定なし(譜面に指定なし)」
   - calibration または frame が無い(カメラなしモード)→ 運指判定なし(音判定のみ。F-01)。
     ログ上は「運指判定なし(カメラなし)」とし、**手が検出できなかった「判定不能(handNotDetected)」とは
     区別する**(F-06 の「判定不能数」の意味を保つため。レビュー指摘)
   - `estimateFinger(frame, note.hand, midi, calibration)`:
     - 推定指 = 譜面指 → OK(無音)
     - 不一致 → **運指ミス**。ビープ A +「指番号: 正解 X / 実際 Y」
     - 判定不能 → 既定では「無視(カウントのみ)」。`FINGER_UNDETERMINED_AS_MISS = false`(P5 で設定 UI 化)。
       **true(ミス扱い)の場合はビープ A + 表示「判定不能(ミス扱い)」**(レビュー指摘 4)
5. duplicateIgnored も判定ログに記録
6. 判定ログエントリ(F-05): タイムスタンプ / 譜面上の位置(eventIndex・measure・posInMeasure)/
   期待値(midi・finger・hand)/ 実測値(押した midi・推定指番号と信頼度)/ 判定結果
7. 集計カウント(総打鍵・音ミス・運指ミス・判定不能)も保持(画面表示用。S-05 の本格集計は P5)
8. **やり直し・小節指定開始は「新しい練習セッション」としてログ・集計をクリアする**
   (F-06 のサマリーが 1 回の練習に対応するように。レビュー指摘 3)

ビープを鳴らすのは UI 側(core は音を出さない=ブラウザ API 非依存を維持)。
判定は Note On ハンドラ内で同期実行(10 章の 200ms 以内は問題なく満たせる)。

### 2. `scoreFollower.ts` への追記

- `setCursor(eventIndex)`: 進行状態をリセットして指定イベントから開始
  (F-05「小節番号で指定し、内部でその小節の最初のイベント index に変換」の受け口。
  小節番号→index の変換は judge.ts にヘルパー `firstEventIndexOfMeasure(song, measure)` を置く)

### 3. ビープ音 `audio/feedback.ts`(F-05)

- Web Audio API 直接使用(仕様 5 章)。AudioContext はユーザー操作(初回打鍵/開始ボタン)で生成
- `beepFingerMiss()` = ビープ A: 低め・ブザー的(矩形波 220Hz・約 150ms を想定。値は聴いて調整)
- `beepNoteMiss()` = ビープ B: 音色を変える(サイン波 880Hz・短め を想定)
- 音量は定数(F-07 の設定 UI は P5)

### 4. 練習画面 `components/PracticeScreen.tsx`(S-04)

- 曲選択(songs レジストリから。現状はテスト曲のみ。正式な S-03 楽曲選択画面は P5)
- 大きな進行表示: 「次に弾く音(音名+指番号+手)」「進行 n / N」(9 章: 遠目でも分かる表示を優先)
- 打鍵ごとの判定表示: 正解 / 音ミス /「運指ミス 指番号: 正解 3 / 実際 2」/ 判定不能(無視)
- カメラプレビュー + ランドマーク + 鍵盤白線オーバーレイ(useHandCamera / drawLandmarks を再利用)
- **一時停止/再開**: 一時停止中の Note On は無視(ログにも残さない)
- **最初からやり直し** / **小節番号を指定して途中から開始**
- 判定ログの直近数件を画面に表示(全ログはメモリ保持。JSON ダウンロードは F-06/P5)
- 曲の完走(finished)で完走メッセージ(結果画面 S-05 への遷移は P5)
- **Note On ハンドラでは `tracker.history.getNearestFrame(msg.timestampMs)` で
  Note On 時刻に最も近いフレームを取り、judge に渡す**(仕様 7.2 重要注記。レビュー指摘 2。
  最新フレーム getLatestFrame を渡す実装ミスをしないこと)
- **一時停止中もカメラ・検出ループは止めない**(再開直後の Note On でも新しいフレームが履歴にあるように)
- **カメラなしモード**: キャリブレーション未実施でも「音判定のみで練習」できる(F-01)。
  その旨のバナーを表示し、運指判定はすべてスキップ。
  カメラ設定の変更でキャリブレーションが無効になった場合も同じバナーに
  **「再キャリブレーションが必要です(P3 タブで実施)」の文言と導線を出す**(無言で降格しない。レビュー指摘 5)
- バーチャル鍵盤を下部に表示(実 MIDI が無い間の入力手段)

### 5. キャリブレーション結果の受け渡し

- App が `calibration` を state で保持。CalibrationDebug に `onCalibrated(calibration)` プロップを追加し、
  ウィザード完了時に App へ渡す。P4 練習タブはそれを使う
- 注意: タブ切替でカメラは再起動されるが、同じデバイス・同じ解像度なら座標系は不変なので
  キャリブレーションは有効なまま。カメラデバイスやミラーを変えた場合は P3 側で破棄される(既存動作)。
  練習画面側でもカメラ変更時は運指判定を無効化してカメラなしモード相当に落とす
- 正式な画面フロー(S-01→S-02→…)への統合は P5〜P6 で行う(現状は開発用タブ構成のまま)

### 6. テスト(`tests/core/judge.test.ts` ほか)

- 音正解 + 指一致 → OK(運指ミスなし)
- 音正解 + 指不一致 → 運指ミス(期待指・実際指がログに入る)
- 音正解 + 判定不能 → 既定で「無視(カウントのみ)」/ `FINGER_UNDETERMINED_AS_MISS=true` なら「ミス扱い」(ビープ A 相当の結果種別)
- 音ミス → 運指判定が走らない(7.3)
- **skipJump → 運指判定が走らず、音ミスとして集計され、スキップイベントがログに記録される**
- **skippedEventIndices 付きの finished(救済で完走)→ 同上(運指判定なし・音ミス扱い)**
- スキップ無しの finished → 通常の正解と同様に運指判定される
- `finger: null` → 運指判定スキップ(判定不能とは別扱い)
- calibration/frame が null(カメラなし)→ 運指判定なしで音判定のみ(判定不能カウントに入れない)
- 判定ログのフィールド(タイムスタンプ・位置・期待値・実測値・結果)と集計カウント
- やり直し(reset)・途中開始(setCursor)でログ・集計がクリアされる
- scoreFollower.setCursor: 指定位置から開始・小節→index 変換ヘルパー

## 仕様上の解釈・判断(レビュー観点)

- 判定不能の扱い・音量・クリック音は F-07(設定 UI)の管轄なので、P4 では constants の既定値のみ
  (判定不能=無視、音=ON、クリック音=なし)。UI 化は P5
- ビープの周波数・波形・長さの具体値は仕様に無いため実装時に耳で調整(「低め・ブザー的」「音色を変える」に従う)
- 判定ログは F-05 の要求どおり P4 で記録し、JSON ダウンロード(F-06)は P5
- 一時停止中の打鍵は「無視(ログにも残さない)」と解釈(仕様に明記なし。練習の中断なので判定対象外が自然)
- カメラなしモードは F-01 の「音判定のみモード」を練習画面側で先行実装(正式な S-01 の分岐は P5)
