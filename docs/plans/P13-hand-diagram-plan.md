# ミスした指の図示(F-12)実装計画

## 背景・目的

実機で練習したところ、運指ミスの表示が「運指ミス 指番号: 正解 1 / 実際 3」という文字だけで、
**和音や両手の場面でどの指が違ったのか直感的に分からない**(開発者が 2026-11-23 に確認)。

さらに計画のレビューで、より根本的な原因が判明した:
**和音は打鍵ごとに判定されるため、1 音目でミスしても、直後の 2 音目の判定で表示が上書きされて消える。**
文字表示すら残らないので「ミスした気がするが何だったか分からない」状態になる。

そこで、**イベント(同時に押す音のまとまり)単位で運指ミスを集め、手の図で示す**。
仕様書に F-12 として追加済み(変更履歴に記載)。

完了条件:

- 和音の途中でミスしても、**そのイベントのミスが図として残る**
- 正解の指と実際に使った指が、**色+形**で区別できる
- タブレット横持ち(960×600)で**スクロールが増えない**

## 仕様書の該当章

- **F-12**: 手の図 / 正解=緑・実際=赤 / **イベント単位でまとめる** / 次の運指ミスまで残す /
  やり直し・曲切替・小節指定開始で消す / **同じ指が両方の役になり得る** / 音名を添える /
  判定不能・運指判定なしでは出さない / 色だけに頼らない / **高さを圧迫しない(カメラに重ねてよい)** /
  外部ライブラリ不使用
- F-05: 文字表示は**残す**(図と併用)
- 7.3 / `src/core/`: **変更しない**(表示だけの追加)
- 9 章: 横持ちでスクロールを出さない。遠目でも分かる表示

## やらないこと

- 判定ロジック・スコアフォロー・運指判定の変更(`src/core/` は触らない)
- 楽譜上でミスした音符に色を付けること(F-11 段階 3。次の作業)
- 結果画面(S-05)のミス一覧に図を出すこと
- 正解時・判定不能時に図を出すこと
- アニメーション

## 画面での置き場所(高さを増やさない)

レビューの実測見積りでは、現状の横持ちレイアウトは **600px にほとんど余裕がない**。
そのため、図は**カメラ映像の右下に重ねて表示**する(`position: absolute`)。
こうすればレイアウトの高さは**まったく増えない**。

- 重ねる先は `.practice-cam`(カメラの列)。**`.cam-frame` の内側には置かない**
  (`.cam-frame` にはミラー表示用の `scaleX(-1)` が掛かることがあり、図まで反転してしまうため)
- 図の大きさは 110px 四方程度。キャプション(音名と指番号)を下に小さく添える
- **「カメラ映像は端末の外に送信されません」の表記(10 章)や、カメラ再試行ボタンを覆わない位置**に置く。
  あわせてオーバーレイに `pointer-events: none` を付け、下のボタンを押せる状態を保つ
- 縦持ち(スマホ)では重ねず、**通常の流れでカメラ映像の下**に出る(DOM 上はカメラ列の中にあるため)
- キャプションが伸びて枠をはみ出さないよう、**凡例は 1 行固定・キャプションは 3 行まで(超えたら「他 n 件」)**、
  `max-height` を付ける。文字は遠目前提なので 12px を下限とする(9 章)
- **カメラが無い構成では運指判定自体が行われない**ため、図も出ない(place はカメラ列なので整合する)

## 実装内容

### 1. `src/components/fingerMiss.ts`(新規・純 TS・テスト対象)

ファイル名は `ScoreView.tsx` + `scoreCursor.ts` の前例に合わせる。
**`HandDiagram.tsx` と `handDiagram.ts` のような大文字違いの組は作らない**
(Windows では解決順の違いでビルドが壊れることがあるため)。

```ts
/** 1 本の指のミス(どの音を、どの指で弾くべきで、実際はどの指だったか) */
interface FingerMiss { midi: number; expectedFinger: FingerNumber; actualFinger: FingerNumber }
/** 片手ぶんのミスのまとまり */
interface HandMisses { hand: Hand; misses: FingerMiss[] }
/** 直近の「運指ミスを含むイベント」のミスを手ごとに集める。無ければ null */
export function collectLastFingerMisses(log: readonly JudgmentEntry[]): HandMisses[] | null
```

- ログを**後ろから**見て、`fingering.kind === "miss"` の最初のエントリを探す
- そのエントリの `eventIndex` と同じエントリをログから集め、miss だけを取り出す
  (= 同じ和音の中のミスがすべて集まる)
- 手は `soundResult.note.hand` から取る(運指ミスは音が正解のときだけ起きるため必ず取れる。
  取れない場合はそのミスを無視する)
- 実際の指は `fingering.estimated.finger`
- 両手にまたがる和音では、**手ごとに分けて**返す(最大 2 件)
- `undetermined`(判定不能。ミス扱いの設定でも)、`skipped`、`notApplicable` は対象外

### 2. `src/components/FingerMissView.tsx`(新規)

```tsx
interface Props { handMisses: HandMisses[] }
```

- 手ごとに**簡略化した手の SVG** を描く(手のひら=角丸の四角、指=角丸の縦長。写実にはしない)
- 左手は**指の x 座標の並びを逆順**にして描く
  (`transform: scale(-1,1)` は使わない。数字まで反転して読めなくなるため)
- 各指に**指番号 1〜5 を必ず描く**
- 色と形の対応(**同じ指が両方の役になっても表せる**):
  - **実際に使った指 = 赤で塗りつぶし**(`#ef5350`)
  - **正解の指 = 緑の太い枠線**(`#4caf50`、3px)
  - 入れ替わり(同じ指が両方)のときは、**赤く塗られた上に緑の枠**が付く
  - それ以外の指 = 灰色(`#555`)
- 図の下に小さく凡例とキャプション: 「**ド4: 正解 3 / 実際 2**」「緑枠=正解 / 赤=実際」
- 判定ロジックは持たない(渡された情報を描くだけ)

### 3. `src/components/PracticeScreen.tsx`(変更)

- `collectLastFingerMisses(judge.getLog())` を呼び、結果があれば `FingerMissView` を描く
  (`lastEntry` ではなく**ログ**を見る。和音の途中のミスが次の打鍵で消えないようにするため)
- 描画場所はカメラ列(`.practice-cam`)の中。カメラ映像に重ねる
- `judge.getLog()` は毎描画で呼んでよい(配列を返すだけで、判定エンジンの状態は変わらない)
- **やり直し・曲切替・小節指定開始**では `judge.restart()` 等でログが消えるため図も消える。
  消えることをブラウザで確認する
- 文字表示(`judgmentView`)は**そのまま残す**

### 4. `src/index.css`(変更)

- `.practice-cam { position: relative }` を**素のルールとして**追加(重ねるための基準)
- `.finger-miss-overlay` の既定は `position: static`(通常の流れ)。
  **横持ちのメディアクエリの中でだけ `absolute`** にする。
  (既定を absolute にすると、横持ちスマホ 844×390 のような画面で意図しない重なりが出るため)
- 幅 110px、半透明の暗い背景、角丸、`pointer-events: none`

## テスト

`tests/components/fingerMiss.test.ts`(新規):

- 運指ミス 1 件を正しく取り出す(手・音・正解の指・実際の指)
- **和音で「1 音目 miss → 2 音目 ok」でも、miss が残る**(今回の主目的)
- **同じイベントで 2 本ミス**したら 2 件とも返る
- **両手同時のミス**は手ごとに 2 件に分かれる
- **指の入れ替わり**(正解 2/実際 3 と 正解 3/実際 2)が両方返る
- そのあと正解の打鍵が続いても、**「最後にミスがあったイベント」を返し続ける**こと
  (仕様 F-12: 次に運指ミスが起きるまで残す)
- 判定不能(`undetermined`、`treatedAsMiss: true` でも)は対象外
- `skipped` / `notApplicable` / 音ミス(`wrongNote`)は対象外
- ログが空なら null

既存 220 件が通ること(`src/core` は変更しないため影響なし)。
`FingerMissView.tsx` は見た目なのでユニットテストは書かず、ブラウザで目視確認する。

## 確認(ブラウザ / 実機)

1. **960×600 で、図が出てもページの高さが変わらない**こと(DevTools で `scrollHeight` を実測)
2. 和音の 1 音目でミス → 2 音目が正解でも**図が消えない**こと
3. 正解の指が緑枠、実際の指が赤塗り。**入れ替わりのときに両方が同じ指に乗る**こと
4. 左手のミスでは**左手の図**(親指の位置が左右で入れ替わる)
5. 「やり直す」「曲を切り替える」「n 小節目から開始」で図が消えること
6. 390×844(縦持ち)で、重ならず通常の位置に出ること
7. 正解のみで弾いたとき・判定不能のときは図が出ないこと
   (判定不能は「ミス扱い」の設定だとビープは鳴るが**図は出ない**。文字だけ出ることを確認)
8. カメラがエラーのとき、図が「カメラを再試行」ボタンを覆って押せなくならないこと

PC でも Web カメラでキャリブレーションすれば運指判定は動くため、**まず PC で 1〜8 を確認**し、
最後にタブレット実機で通しの確認を開発者に依頼する。

## 技術的な注意点・リスク

- **高さを増やさないこと**が最優先。重ねる方式なら 0 だが、万一レイアウトに影響したら
  カメラ枠(22dvh)か楽譜(56dvh)から高さを譲る
- 図と文字表示が食い違って見える場合がある(文字は最後の打鍵、図は最後にミスしたイベント)。
  **図のキャプションに音名と指番号を書く**ことで、どの打鍵の話か分かるようにする
- 緑と赤は色覚によっては最も見分けにくい組み合わせ。**塗りと枠**という形の差を必ず付ける
- 一時停止中も図は残る(消す理由がないため)。この挙動は意図的
- カメラが途中で止まった場合、直前の図が残り続ける。実害は無いので許容する
