# ピアノ運指チェッカー

ピアノ初心者向けの運指(指遣い)練習支援 Web アプリ(卒業制作)。
カメラで手を認識し、MIDI キーボード入力と譜面を照合して、違う指で弾いたことをリアルタイムに知らせる。

仕様は [piano-fingering-app-spec.md](piano-fingering-app-spec.md) を参照(このファイルが唯一の正)。

## セットアップ

Node.js 22 以上が必要。

```bash
npm install
npm run dev    # 開発サーバー起動(http://localhost:5173)
npm run test   # ユニットテスト(Vitest)
npm run build  # 型チェック + 本番ビルド
```

## バーチャル MIDI キーボードのキー配置(F-02)

MIDI キーボード実機がなくても、画面上の鍵盤のクリック/タップ、または PC キーボードで演奏できます。

| PC キー | 音 |
|---------|-----|
| A | ド |
| W | ド♯ |
| S | レ |
| E | レ♯ |
| D | ミ |
| F | ファ |
| T | ファ♯ |
| G | ソ |
| Y | ソ♯ |
| H | ラ |
| U | ラ♯ |
| J | シ |
| K | 高いド |

- 「+ オクターブ / − オクターブ」ボタンで音域を移動できます(初期位置はド4=中央のド)
- PC キーは表示範囲の下のオクターブに対応します

## P1 の動作確認手順

1. `npm run dev` で起動し、ブラウザで http://localhost:5173 を開く
2. 画面に「次に弾く音: ド4(指1 / 右手)」と表示される
3. A, S, D, F, G, F, D, S, A の順に押す(=ドレミファソファミレド)
   → 打鍵ごとに「正解」と表示され、進行が進み、最後に「演奏終了」になる
4. わざと違うキーを押す → 「音ミス」と表示され、進行が止まる(正しい音で回復)
5. 同じ間違いを 2 回続けると「弾き飛ばし」救済が働き、先のイベントへジャンプする(仕様書 7.1)
6. 「最初からやり直す」で進行がリセットされる

## P2 の動作確認手順(カメラ)

PC の Web カメラが必要です(タブレットで確認する場合は内蔵カメラを使うので不要)。

1. `npm run dev` で起動し、上部タブの「P2: カメラ確認」を開く
2. ブラウザのカメラ権限を許可する → プレビューが表示される
3. 両手をカメラに映す → 手ごとに 21 点のランドマークと骨格線が追従して描画される
   (左手=水色 / 右手=オレンジ。**実際の手と左右が逆に表示される場合は `src/core/constants.ts` の
   `SWAP_HANDEDNESS` の切替が必要なので報告してください**)
4. 「認識状態」に検出中の手の数・信頼度・処理 fps が表示される(PC で 20fps 以上が目標)
5. 「左右反転(ミラー)表示」を ON にすると表示だけが反転する(内部の座標系は変わらない)
6. 権限を拒否した場合はエラーメッセージと再試行ボタンが表示される

カメラ映像は端末の外に一切送信されません(すべてブラウザ内で処理)。

## P3 の動作確認手順(キャリブレーション + 指特定)

実カメラと(実 MIDI キーボードが無ければ)バーチャル鍵盤を使います。
**カメラは鍵盤の上方に置き、鍵盤が画面の下側になる向き**で映してください。

1. `npm run dev` で起動し、「P3: キャリブレーション・指特定」タブを開く
2. カメラ権限を許可し、「キャリブレーション開始」を押す
3. 手順2: 実際の鍵盤の低い方の鍵盤の上に指を置き、その位置で画面下のバーチャル鍵盤の対応する音を押す
   (実 MIDI キーボードがあればそのまま押すだけ)。手が映っていないと記録されずやり直しになる
4. 手順3: 高い方の鍵盤(1 オクターブ以上離す)で同様に行う
5. 手順5(確認): 適当な鍵盤を数回押すと、推定位置とのズレ(半音単位)が一覧表示される。
   0.5 半音を超える打鍵があると再キャリブレーション推奨が出る(強制ではない)
6. 「キャリブレーション完了」を押すと指特定デバッグに移り、鍵盤を押すたびに
   **推定された指番号と信頼度(距離・マージン)**、または判定不能の理由が表示される
7. カメラやミラー設定を変えるとキャリブレーションは破棄され、最初からやり直しになる(仕様どおり)

## P4 の動作確認手順(練習モード)

### カメラなし(音判定のみ)で試す場合

1. `npm run dev` で起動し、「P4: 練習」タブを開く(「音判定のみモード」のバナーが出る)
2. バーチャル鍵盤で曲を弾く → 正しい音は「正解(音のみ判定)」、違う音は「音ミス」+ ビープ音
3. 一時停止 / 最初からやり直す / 小節番号を指定して途中から開始、が使える
4. 「判定ログ」を開くと打鍵ごとの記録が見える

### 運指判定まで試す場合(P4 の完了条件)

1. 先に「P3: キャリブレーション・指特定」タブでキャリブレーションを完了する
2. 「P4: 練習」タブへ移ると、同じカメラで運指判定つきの練習になる
3. 白線の位置に**正しい指**を置いて対応する音を弾く → 「正解(指 N)」
4. **わざと違う指**で弾く → 低いブザー音(ビープ A)+「運指ミス 指番号: 正解 X / 実際 Y」
5. 違う鍵盤を弾く → 高めの短い音(ビープ B)+「音ミス」(音色の違いを確認)
6. 指が判定できない打鍵は「判定不能」として数えるだけでミスにはしない(既定設定)

## P5 の動作確認手順(結果サマリー + 設定)

1. 「P4: 練習」タブで曲を最後まで弾く → **自動で結果サマリー(S-05)**が表示される
   (途中でやめる場合は「練習を終了して結果を見る」ボタン)
2. 結果画面: 総打鍵数・音ミス・運指ミス・判定不能の集計と、
   「◯小節目の◯番目の音: 3 の指のところを 2 で弾いた」形式のミス一覧が出る
3. 「判定ログを JSON でダウンロード」で全打鍵の記録が保存できる(卒論の評価実験用データ)
4. 「⚙ 設定」(S-06): フィードバック音の ON/OFF・音量、正解時クリック音、
   判定の厳しさ(判定不能を無視/ミス扱い)、運指判定の対象の手(両手/右のみ/左のみ)
5. 「もう一度練習する」で新しいセッションが始まる

## 楽曲の追加方法

曲は **運指付きの MusicXML** から追加します。方法は 2 つあります。

### A. アプリから追加する(F-09。おすすめ・コード不要)

1. MuseScore などで曲を開き(運指がない場合は MuseScore 上で**指番号を付ける**)、
   「ファイル → エクスポート → MusicXML → **非圧縮(.musicxml)**」で保存する
   - ⚠️ MuseScore の既定は**圧縮(.mxl)**です。必ず**非圧縮**を選んでください
   - ⚠️ **MIDI ファイルは使えません**(規格上、運指情報を保存できないため)
2. 練習画面の **「楽譜を追加(MusicXML)」** ボタンからファイルを選ぶ
3. すぐに曲一覧へ追加され、そのまま練習できます

- 曲名は**ファイル名**になります(MuseScore の曲名は初期値のままのことが多いため)
- 追加した曲は**ブラウザに保存**され、次に開いたときも残ります(端末内のみ。外部には送信されません)
- 追加した曲を選ぶと「**この曲を削除**」ボタンが出ます

### B. コマンドでリポジトリに組み込む(内蔵曲にする場合)

配布物に最初から含めたい曲は、変換スクリプトで JSON にしてリポジトリに入れます。

1. 上記と同じ手順で MusicXML(非圧縮)を用意する
2. 変換スクリプトを実行:

   ```bash
   node tools/musicxml2json.mjs beyer-08.musicxml --id beyer-08 --title "バイエル 8番" --difficulty 1 --out src/songs/beyer-08.json
   ```

3. 警告(運指の無い音符・装飾音の除外など)が出たら内容を確認する
4. `src/songs/index.ts` に 2 行追加してレジストリに登録する:

   ```ts
   import beyer08Json from "./beyer-08.json";
   export const builtinSongs: Song[] = [doremi, kakkou, londonBridge, beyer08Json as unknown as Song];
   ```

5. `npm run dev` で起動すると練習画面の曲選択に表示される

※ この変換スクリプトには Node.js **22.18 以上**が必要です(変換ロジックの TypeScript を直接読むため)。

### 変換の仕様(A・B 共通)

**変換処理は `src/songs/musicxml.ts` の 1 箇所にしかありません。**
アプリもコマンドも同じ関数を呼ぶため、**どちらで変換しても結果は必ず同じ**になります(仕様書 F-09)。

白鍵・黒鍵の音高(♯♭対応)/ 和音・両手同時(大譜表の backup)を 1 イベントに集約 /
staff 1=右手・staff 2=左手 / タイの 2 音目以降・休符・装飾音は除外 / 運指の無い音符は
`finger: null`(運指判定をスキップ)。

## 音について(F-08 参照音)

MIDI キーボードは音源を持たない機種が多いため、**押した音はアプリが鳴らします**(参照音)。

- 鍵盤を押すとその高さの音が鳴り、離すと止まります(実際のピアノと同じ)。和音も鳴ります
- 譜面と違う音を押しても鳴ります(実際のピアノと同じ挙動)
- ミス時のビープ音(F-05)とは別物で、**一時停止中でも参照音は鳴ります**
- ブラウザの制限で、ページを開いた直後は音が出ないことがあります。
  その場合は「🔇 音を出すには画面を一度タップしてください」の案内が出るので、画面を一度タップしてください
  (**MIDI キーボードを弾くだけでは解除されません**)
- 音色はオシレーターの合成音です(音源ファイルは読み込まないため、遅延が最小になります)

## MIDI キーボードを使う(F-01)

**Chrome または Edge** が必要です(Web MIDI API は Firefox・Safari では使えません)。

1. キーボードを USB ケーブルで接続する(Bluetooth の場合は先に OS 側でペアリング)
2. 練習画面またはキャリブレーション画面の「**MIDI 機器に接続**」ボタンを押す
3. ブラウザの許可プロンプトで「許可」
4. 「MIDI 機器」のドロップダウンからキーボードを選ぶ → そのまま弾くと判定が動く

- キーボードを選んでいる間も**バーチャル鍵盤は使えます**(実機不調時の代替・テスト用)
- USB を抜くと「切断中」と表示され、挿し直すと自動で再接続します
- 一覧に出ない場合は、OS の Bluetooth 設定でペアリングを確認してください。
  Windows では Bluetooth が不安定なことがあるため USB 接続を推奨します(仕様書 3.1)

## スマホで使う / 公開する(P6)

Android スマホ・タブレットで動かすには HTTPS 配信が必要です(カメラ・MIDI は HTTPS 必須)。
手順とチェックリストは **[docs/android-check.md](docs/android-check.md)** にまとめています。

- **GitHub Pages で公開**: このリポジトリを GitHub に push し、Settings → Pages の Source を
  「GitHub Actions」にすると、`.github/workflows/deploy.yml` が自動でビルド&デプロイします
  (base パスはリポジトリ名から自動導出)。公開されるのはアプリのページだけで、カメラ映像・練習データは
  端末外に送信されません。※ 無料プランでは、Pages で公開するにはリポジトリを **Public** にする必要があります(Private にすると公開サイトが止まります。Private での公開は有料プラン)
- **PWA**: 配信後、Android Chrome の「ホーム画面に追加」でアプリのように起動できます
  (オフライン対応は必須ではないため、手認識モデルはオンライン取得です)

ローカルでビルドを試すには:

```bash
npm run build      # dist/ に本番ビルド(PWA の manifest と Service Worker を含む)
npm run preview    # ビルド結果をローカルで確認
```

## ディレクトリ構成

仕様書 13 章に準拠。判定エンジン(`src/core/`)は UI・ブラウザ API に依存しない純 TypeScript で、`tests/core/` にユニットテストがある。

```
public/
  mediapipe/   MediaPipe の WASM ランタイムと手認識モデル(自前配信)
src/
  core/        判定エンジン(スコアフォロー・指特定・運指判定。テスト対象)
  midi/        MIDI 入力(バーチャル鍵盤 / 実 MIDI デバイス / 共通インターフェース)
  vision/      手認識(MediaPipe ラッパー / ランドマーク履歴 / キャリブレーション計算)
  audio/       音(ビープ / 参照音 / 共有 AudioContext)
  songs/       楽曲 JSON・MusicXML 変換・追加曲の保存
  components/  React コンポーネント(画面)
tools/
  musicxml2json.mjs  MusicXML → JSON 変換コマンド(変換本体は src/songs/musicxml.ts)
gakufu/        元の楽譜ファイル(MusicXML)
tests/         Vitest ユニットテスト(core / vision / midi / audio / songs / components)
```
